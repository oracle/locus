# Control-layer conformance fixtures, version 1

These files pin what a port of the Locus governance core has to reproduce
byte for byte. Every file is generated by `scripts/conformance_export.py`
from a fixed clock, fixed inputs and signing keys derived from a fixed seed,
and `tests/unit/test_conformance_fixtures.py` regenerates them on every run
and fails on any difference.

**Stability.** `v1` does not change once published. A change to a hash input,
a record field, a sentence in a report or a document format is a new
`conformance/v2` directory next to this one, with its own README; `v1` stays
as it is so a port that passed it keeps passing it.

A port that reproduces every vector here interoperates with the Python SDK:
a trail it signs verifies with `locus audit verify --key --head`, a trail the
SDK signs verifies in the port, a policy file hashes the same on both sides,
and an admission writes the same line.

## Layout

| Directory | What it pins |
|---|---|
| `canonical-json/` | The canonical JSON the hashes are taken over, with its SHA-256 |
| `audit/` | Hash-chained audit trails, unsigned, signed and across a key rotation, the fixture keys, and one file per tamper class with the report the check returns |
| `policies/` | Policy documents with their hash, lint findings and decisions; malformed documents with the error key |
| `approvals/` | Call digests and approval ids; decision sequences and the record they end in |
| `admission/` | Admissions under a fixed clock and the exact `action-admission` line each writes |
| `tools/` | A dependency-free Node script that recomputes the digests and verifies the signatures from another language |

Timestamps start at `2026-01-01T00:00:00+00:00` and advance one second per
reading of the clock.

## Canonical JSON

Every digest in the core is SHA-256, as lower-case hex, over the UTF-8 bytes of
a JSON document serialised with these rules:

1. Object keys sorted by Unicode code point (not by UTF-16 code unit: U+FF01
   sorts before U+1F600), at every depth. Arrays keep their order.
2. Compact separators: `,` between items and `:` between a key and its value,
   with no whitespace anywhere.
3. Numbers as Python prints them. An integer prints in full at any size. A
   float always carries a decimal point or an exponent: `0.0`, `1.0`, `100.0`,
   `-0.0`; the shortest representation that round-trips; the exponent form
   below `1e-4` and from `1e16` up, written `1e-05` and `1e+16`. `1` and
   `1.0` are different bytes and different hashes, so a port must keep the
   integer/float distinction through parsing: a plain `JSON.parse` erases it.
4. Values that are not JSON types are rendered with `str()` (`default=str`),
   so a timestamp object hashes as its text.
5. Two escaping modes. The audit trail, the policy hash and the approval
   digest use ASCII mode: every character outside `0x20`–`0x7E` becomes a
   `\uXXXX` escape (lower-case hex, surrogate pairs for astral characters,
   `\u007f` for DEL), plus the short escapes `\"`, `\\`, `\n`, `\r`, `\t`,
   `\b`, `\f`. The tool-call integrity form uses UTF-8 mode: only `"`, `\`
   and the control characters below `0x20` are escaped; everything else is
   written as UTF-8. `/` is never escaped in either mode.
6. No Unicode normalisation: NFC and NFD spellings of the same text are
   different keys.

`canonical-json/vectors.json` is a list of `{name, mode, input, input_json,
canonical, sha256, note}`. `mode` is `ascii` or `utf8`. `input_json` is the
input as JSON text and is the authoritative form, for parsers that preserve
number spellings; `input` is the same value for readers. `canonical` is the
string the rules above produce and `sha256` its digest. Three vectors tie the
rules to the other directories: `audit-entry-body` is the hash of record 0 of
the unsigned trail, `policy-default` is `policies/default.hash`, and
`approval-call` is the first digest in `approvals/digests.json`.

## Audit trails

A record is one JSON object per line with exactly these fields, in this order:
`seq`, `ts`, `event_type`, `payload`, `prev_hash`, `hash`, and, only when the
trail signs, `key_id` and `signature`. The line is written with default
separators (`", "` and `": "`) and ASCII escaping; the line's layout is not
part of the hash.

- `hash` is the canonical digest (ASCII mode) of the object
  `{"seq", "ts", "event_type", "payload", "prev_hash"}`.
- `prev_hash` of record 0 is the genesis anchor, 64 zeros; every later record
  carries the `hash` of the one before it. The trail's head is the last
  record's `hash` (the genesis anchor for an empty trail).
- `signature` is Ed25519 over the ASCII bytes of the 64-character hex `hash`,
  encoded as standard base64 with padding. A verifier decodes strictly: a
  signature that is not valid base64 fails the record.
- `key_id` names the key. When no id is given it is the first 16 hex
  characters of SHA-256 over the raw 32-byte public key (the last 32 bytes of
  the SubjectPublicKeyInfo DER). `audit/keys/2ee9031729dbde22.pub.pem` carries
  its derived id; `conformance-v1-rotated` is an explicit one.
- A reader rejects a line that is not a record: not JSON, or an object with a
  missing or extra field. Blank lines are skipped.

The check returns `{ok, records, head, broken_at, problem}`. `records` counts
the lines that parsed as records, `head` is the last parsed record's hash,
`broken_at` is the index of the first bad record or `null` when the problem
is not one record, and `problem` is one of these sentences (empty when `ok`),
tested in this order:

1. `N line(s) are not audit records`
2. `record i carries seq s: a record was removed or moved`
3. `record i does not follow record i-1`
4. `record i was changed after it was written`
5. `the chain does not end at the expected head: records were cut off`
6. `record i is not signed by a trusted key` (unsigned record, unknown key id,
   bad base64, or a signature that does not verify)

Each of `audit/unsigned/`, `audit/signed/` and `audit/rotated/` holds
`trail.jsonl`, `expected_head` (the head as text) and `check.json`:
`{trail, expected_head, checks: [{keys, expected_head, report}]}`. `keys` is
the list of key ids the verifier trusts (load `audit/keys/<id>.pub.pem`) or
`null` for a chain-only check; `expected_head` is the anchored head or
`null`. `rotated` is signed by the primary key for records 0–1 and by
`conformance-v1-rotated` from record 2 on.

`audit/tamper/<class>.jsonl` is the signed trail with one change, described
in `<class>.check.json` (`base`, `description`, `checks`). The classes are
`edited-payload`, `reordered-records`, `deleted-record`, `truncated-file`,
`unknown-key-id`, `bad-base64-signature`, `wrong-signature`, `extra-field`,
`edited-prev-hash`, `rebuilt-chain` and `not-a-record-line`. Two of them
carry more than one check: a truncated trail passes without an expected head,
and a rebuilt chain (an edit with every later hash recomputed) passes the
chain check alone and fails on the head and on the signatures.

The private keys under `audit/keys/` are published test material: they are
derived from a seed phrase in the export script, sign these fixtures and
nothing else, and must never be used outside them.

## Policies

A policy document has `schema: "locus.control.policy/v1"` and one key per
rule, in this order: `require_verification_score`, `max_blast_radius`,
`require_human_for`, `deny_for`, `min_severity`, `require_sandbox_for`,
`version`, `require_human_over_usd`, `spend_limit_usd`, then an optional
`governs: {environments, kinds}` block. The files here were written by the
SDK's own emitter, so a port's `dump` is expected to produce the same text:
JSON with two-space indentation, or YAML with every string as a double-quoted
JSON string (so `yes`, `on` and `1.0` stay strings) and exponents spelled
out. YAML is read with the YAML 1.1 schema: an unquoted `yes` is a boolean
and is rejected as a label.

For each document `<name>.policy.<json|yaml>`:

- `<name>.hash`: the canonical digest (ASCII mode) of the rules as a JSON
  object, label sets as sorted lists, the severity as its name, `null` for
  an unset limit. The `schema` and `governs` keys are not part of it; the
  `version` label is.
- `<name>.lint.json`: the lint report, `{ok, source, policy_hash, findings:
  [{code, rule, label, message}], notes}`, with `source` empty. Findings come
  in the order `unreachable-rule`, `uncovered-environment`, `kind-never-held`,
  each sorted by label; the environments and kinds come from `governs`.
- `<name>.decisions.json`: a list of `{action, verdict, finding, spent_usd,
  expected}`. `action` is the JSON form of an action (`name`, and optionally
  `asset`, `blast_radius`, `environment`, `kind`, `tags`, `cost_usd`, with
  the defaults `""`, `1`, `"unknown"`, `""`, `[]`, `0.0`); `verdict` is
  `{survives, confidence, evidence_quality}` or `null`; `finding` is
  `{severity}` or `null` (only the severity is weighed); `spent_usd` is what
  the scope has already spent. `expected` holds `outcome` (`allow`,
  `require_human` or `deny`), `checks` (the sentences of the rules that
  fired, in rule order), `reason` (the checks joined with a semicolon and a
  space, or `all policy checks passed`) and `rules` (every rule weighed,
  fired or not,
  as `{rule, outcome, detail}`, in the order `deny_for`,
  `require_sandbox_for`, `min_severity`, `require_verification_score`,
  `max_blast_radius`, `require_human_over_usd`, `spend_limit_usd`,
  `require_human_for`). The strongest fired outcome wins
  (`deny` > `require_human` > `allow`). Money prints as `$9,900.00`;
  confidences and bars with two decimals; label lists as a sorted Python
  list literal.

`policies/malformed/<name>.policy.<json|yaml>` must fail to load, and
`<name>.error.json` gives the `key` the error names (`""` when the problem is
the whole document, `require_human_for[1]` for an item, `governs.kinds` for a
nested key) and the message. The key is normative; the message is the SDK's
wording and, for the two documents that do not parse, only its prefix.

## Approvals

`approvals/digests.json` is a list of `{principal, tool, arguments, context,
digest, approval_id, note}`. The digest is the canonical digest (ASCII mode)
of `{"principal", "tool", "arguments"}` plus a `"context"` key only when the
context is non-empty, so an empty context hashes like none. The first
approval id for a call is `appr-<digest[:16]>-1`: the prefix `appr-`, the
first 16 hex characters of the digest, and a counter starting at `1`; a later
record for the same call, after the earlier one was consumed, counts up
(`-2`).

`approvals/sequences/<name>.json` runs a store from empty under the fixed
clock: `{authority, steps, results, final}`. `authority` is `null` or
`{rules: [{labels, approvers, roles, quorum, allow_self_approval, name}],
delegations: [{grantor, grantee, expires_at, labels}], roles: {principal:
[role]}, count_once}`. Each step is one of `submit` (`principal`, `tool`,
`arguments`, `reason`, `labels`, `context`), `decide` (`verdict`, `by`,
optional `reason` and `arguments`), `consume`, `state` and `pending`; a step
names its record by `ref` (the index of the `submit` step that opened it) or
by a literal `approval_id`. `results` has one entry per step:
`{approval_id}`, `{status}`, `{state}`, `{pending: [ids]}` or `{error:
{type, message}}`, where `type` is `ApprovalAuthorityError`, `ValueError` or
`KeyError`. `final` maps every opened approval id to its full record:
`approval_id`, `digest`, `principal`, `tool`, `arguments`, `status`,
`reason`, `created_at`, `verdict`, `decided_by`, `decided_at`, `labels`
(sorted), `approvals`, `rejections`, `context`, `approved_arguments`. A
record's `created_at` is read from the clock when it is submitted and every
decision reads it once more, so the timestamps follow the step order.

## Admission

`admission/cases.json` is a list of cases, each admitted on a fresh trail
whose clock returns `clock`: `{name, policy, action, verdict, finding,
approved_by, ledger, context, advisor, judgement, clock, expected}`. `policy`
names a document under `policies/`; `ledger` is `null` or `{scope, spent}`,
the scope's spend before the decision; `advisor` is `null`, `{advice}` (an
outcome string, a word the gate does not know, or `null` for no opinion) or
`{raises}` (a model that fails); `judgement` is `null` or a judge verdict
`{tool, verdict, reason, model, source, error}`.

`expected` holds `admitted`, `error` (the exception message, `action 'name'
not admitted (outcome): reason`, or `null`), `line` (the one record the
trail wrote, byte for byte) and `spent_after` (the scope's spend after the
call, `null` without a ledger: a refused or held action spends nothing). The
record's `event_type` is `action-admission` and its payload has `action`,
`asset`, `outcome`, `reason` and `policy_hash` always; `cost_usd`,
`spent_usd` and `spend_scope` with a ledger; `policy_outcome` and
`model_outcome` when an advisor was given; `judge` when a judgement was;
`approved_by` when a hold was approved; `context` when one was passed. An
advisor is consulted only on an allow and can only make the decision
stricter; a judge verdict is folded in after the policy and can only do the
same; a word outside `allow`, `hold` and `deny` is read as a hold.

## Running the vectors from a port

1. Implement the canonical form and check every entry of
   `canonical-json/vectors.json`: serialise `input` (parsed so that number
   spellings survive) in the vector's `mode`, compare with `canonical`, hash
   it, compare with `sha256`.
2. For every `check.json` under `audit/`, read the trail, run the check with
   the named keys and head, and compare the report field by field.
3. Load every policy document, compare the hash, the lint report and each
   decision; load every malformed document and compare the error key.
4. Compute every digest and id in `approvals/digests.json`; replay every
   sequence and compare `results` and `final`.
5. Replay every admission case under its clock and compare `line` byte for
   byte, `admitted`, `error` and `spent_after`.

`tools/check.mjs` is the first two steps' digest and signature half, written
against Node's standard library alone:

```sh
node conformance/v1/tools/check.mjs
```

It prints the number of vectors and signatures it checked and the key id it
derives from each public key, and exits non-zero on the first mismatch. The
unit test runs it when `node` is on the path and compares the counts.

## Regenerating

```sh
python scripts/conformance_export.py          # rewrite conformance/v1
python scripts/conformance_export.py --check  # exit 1 if anything would change
```

Regenerating is for a new version. If the script's output for `v1` ever
differs from what is committed, the SDK's behaviour changed, and the change
ships as `conformance/v2` together with the port release that implements it.
